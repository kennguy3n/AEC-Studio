# Phases

High-level summary of the AEC Studio delivery phases (currently 0–16). The
canonical, up-to-date status — including per-item check marks, exit
criteria, and changelog — lives in
[PROGRESS.md](PROGRESS.md). This file is intentionally short so it
stays readable as the project grows.

| Phase | Goal (one line) | Status |
|---|---|---|
| **0 — Repository & docs** | Initialize repo, AGPL-3.0 license, and the full documentation suite. | `DONE` |
| **1 — Technical validation** | Stand up the Rust workspace, Electron shell, native bridge, project package format, and AI sidecar runtime end-to-end. | `DONE` |
| **2 — ArchViz / Interior Studio MVP** | A solo interior designer can take an apartment from new project to client renders without leaving the app. | `DONE` |
| **3 — 2D CAD module** | Drafters can produce construction documentation in pure 2D and roundtrip DXF cleanly. | `DONE` |
| **4 — BIM Lite / IFC** | Small studios can import IFC, classify, edit properties, generate schedules + BOQ-lite, and re-export with GUID preservation. | `DONE` |
| **5 — Render pipeline hardening** | Renders are reliable, reproducible, and fast enough to be part of the daily delivery workflow. | `DONE` |
| **6 — Deliver and export** | A studio lead can ship a complete delivery package — client, contractor, BIM, revision-tracked — from one project. | `DONE` |
| **7 — Optional KChat integration** | Teams using KChat can publish AEC Studio artifacts and route review comments back to the audit trail without giving up local-first. | `DONE` |
| **8 — Extension system** | Asset packs, templates, schedules, export targets, AI tools, and importers ship as Ed25519-signed third-party extensions with a typed permission model. | `DONE` |
| **9 — Native render & BIM engine** | Replace the Blender and IfcOpenShell worker processes with in-process Rust implementations (SAH BVH, wgpu compute path tracer, PBR rasterizer preview, STEP parser/writer, geometry tessellator). No external runtime dependency for rendering or IFC. | `DONE` |
| **10 — N-API bridge completion** | Wire every `BridgeBackend` method through the N-API boundary — no more in-process fallbacks. Promote the 9 `draft.*` / `deliver.*` methods listed in `NATIVE_FALLBACK_METHODS` into the wired set so every gesture journals through `command_apply` (Immediate transaction, audit chain, undo-able). | `DONE` |
| **11 — Real domain depth** | Replace stubs and scaffolding with real implementations across the workspace: AI accept-diff → `command_apply`, template instantiation produces real walls/floors/ceilings/rooms, filesystem revision snapshots + BLAKE3 version diff, DXF round-trip fidelity, DWG bridge wiring, real PDF / SVG / glTF exports, asset import pipeline with LOD chain + thumbnails, real IFC schedules from project data, SQLite-backed render job persistence, incremental constraint solver, IES profile parsing, BLAKE3 audit-chain verification, per-OS thermal monitor + governor backoff, and end-to-end user-journey integration tests for the interior, drafter, and PM workflows. | `DONE` |
| **12 — Production depth, KChat local IPC, viewport pipeline** | Take every Phase 0–11 surface from "works in tests" to "ships to users". `LocalIpcTransport` + `LocalIpcPublisher` + `KChatDiscovery` connect to a real KChat Desktop instance over a UNIX socket / named pipe; the wgpu viewport ships a real adapter + `RenderPipeline` + `SurfaceManager` with frame coalescing; deliver packs carry real PNGs / XLSX / PDFs / IFC / SVG content from the project graph (no placeholder bytes); the AI sidecar adapter spawns a real `llama-server` with `/health` checks, GBNF-constrained `/completion`, idle unload, and crash restart; the final render pipeline + PBR preview + IES GPU texture + NLM denoiser + tile progress streaming light up the production render path; and a cross-cutting hardening pass adds `ProjectPackage::open` forward-only migrations with pre-migration backup, memory-pressure eviction in the governor, SQL-backed undo/redo journal, plus Phase 5 and Phase 7 end-to-end journey tests. | `DONE` |
| **13 — Renderer UX wiring, placeholder elimination, file-picker integration, active project state, UI polish** | Take the Phase 12 production-depth surfaces and finish the renderer-side experience: every mode page (BIM / Design / Draft / Deliver / Render / Home) is wired to the live active-project state via the new `useActiveProject` React context + `<RequireProject>` route guards; `demo://` placeholder paths are removed from production code; Electron file-picker IPC (`dialog.openFile/openDirectory/saveFile`) replaces hard-coded paths in import/export flows; a global toast system, status-bar wiring (dirty/saving/saved + undo/redo + render-queue chip), keyboard-shortcut help overlay, per-mode error boundaries, and a debounced ResizeObserver on the viewport polish the shell. Group B (backend `placeholder_*` elimination + real `DeliverPackContext`) and Group F (acceptance-criteria benchmarks + Phase 6 deliver / Phase 8 extension e2e journeys) ship as Phase 14. | `DONE` |
| **14 — Deferred Phase 13 follow-ups, `demo://` cleanup, journey validation, benchmarks, KChat integration audit** | Land the two groups deferred from Phase 13 (real `DeliverPackContext` from project state + acceptance-criteria benchmarks + Phase 6/8 user-journey e2e) and finish the production-polish pass: remove every remaining `demo://` reference from non-changelog source; resolve / re-frame TODO / "future PR" / "follow-up" archaeology across the workspace; validate all 15 PROPOSAL.md acceptance criteria (Journeys A–E, three each) with `journey_[a-e]_*.rs` Bridge tests; close the XLSX-to-row-list round trip (`aec_bim::xlsx_reader`) so `ScheduleView` displays real schedule data; verify the no-GPU graceful-degradation path end to end; audit the existing Phase 12 KChat socket transport against the real `uneycom/uney-chat-desktop` codebase (finding: KChat Desktop's Extension Platform is a JS-only sandbox with no socket listener, so the Phase 12 socket transport is vestigial — the integration is replatformed onto a loopback HTTP API + `.kcz` companion extension + `aecstudio://` deeplinks in Phase 15, following the Tessera / KCreate pattern); final docs audit on PROGRESS.md / PHASES.md / README.md / ARCHITECTURE.md / PROPOSAL.md. | `DONE` |
| **15 — KChat integration replatform: loopback HTTP API + `.kcz` companion extension + `aecstudio://` deeplinks** | Replace the vestigial Phase 12 socket / named-pipe transport with the Tessera / KCreate-style topology: AEC Studio's Electron main process exposes a 127.0.0.1-only HTTP API (bearer + Host-header SSRF guard + 64 KiB body cap + atomic-rename `0600` discovery file at `{userData}/aec-kchat-port.json`) for the KChat-side companion to call. A signed `.kcz` extension running inside KChat Desktop's Extension Platform sandbox reads the discovery file, calls AEC Studio's loopback API to pick up publish-to-thread / review-comments payloads, and publishes them into the KChat thread via the existing `invokeProcedure("kchat.send_message")` / `invokeProcedure("kchat.query_messages")` host calls. AEC Studio registers `aecstudio://` as a default protocol client with single-instance lock + `second-instance` / `open-url` handlers + pre-ready deeplink buffering for inbound deeplinks (e.g. `aecstudio://review?thread=<id>`), and a rate-limited `kchat:openInDesktop` IPC for outbound `kchat://app/conversation/<id>` navigation through `shell.openExternal()`. The Rust core drops `kchat_transport.rs` / `local_ipc_publisher.rs` / `kchat_discovery.rs` (sockets); `kchat.rs` / `kchat_sync.rs` / `kchat_config.rs` stay (transport-agnostic). `kchat_state.rs` switches from socket probe to loopback-API heartbeat detection, `service.rs` / `napi_api.rs` rewire publish + ingest through the new HTTP-mediated publisher, and `KChatStatusReport` surfaces loopback port + extension heartbeat in place of the old socket path. Renderer Settings / `KChatStatusIndicator` / `PublishCardModal` follow. Tests replace socket mock-server suites with loopback HTTP suites (bind verification, discovery-file shape, bearer + Host-header negative cases, route surface, deeplink parsing). Cargo `kchat` feature on `aec_core` strips socket/pipe deps and gates the new loopback API + HTTP publisher instead. | `DONE` |
| **16 — Per-extension boot diagnostics IPC** | Address the Phase 14 follow-up that broken extensions failed silently at bridge boot (`unwrap_or_default()` on the registry load + `let _ =` on asset-pack install errors at `service.rs:1428-1466`). New fault-tolerant loader `aec_core::extensions::load_with_diagnostics()` returns `(ExtensionRegistry, Vec<ExtensionLoadDiagnostic>)` instead of erroring on the first malformed manifest; each `ExtensionLoadDiagnostic` carries the extension id (when knowable), the source path, an `ExtensionLoadStage` (one of `manifest_read`, `manifest_parse`, `manifest_validation`, `unsafe_path`, `signature_verification`, `duplicate_id`, `asset_pack_install`, `ai_tool_resolution` — wire-stable via `as_wire_str()`), and a human-readable error message. Companion `aec_assets::install_asset_packs_collect_errors()` returns per-extension failure tuples (vs. the previous single `Result<()>`) so a DB-corruption-mid-install case surfaces N rows instead of one. `BridgeService` buffers diagnostics from three boot stages — loader, asset-pack install, AI-tool resolver pre-walk — into a `Vec<ExtensionLoadDiagnostic>` exposed via the `extension_load_diagnostics()` getter. N-API surfaces `ExtensionLoadDiagnosticJs` (snake_case→camelCase auto-conversion) and the `extension_load_diagnostics()` napi export. Electron adds a new top-level IPC namespace `extensions:` (independent of `kchat:`) starting with `extensions:listLoadDiagnostics`, threaded through `BridgeBackend.extensionsListLoadDiagnostics()` + `preload.ts` `aec.extensions.listLoadDiagnostics()`. Settings page renders a read-only "Extension load diagnostics" card (hidden when empty) with human-readable stage labels. Fault tolerance is the load-bearing property: broken extension manifests never block renderer boot or core functionality; the diagnostics surface is purely observational. | `DONE` |
| **17 — Top-level product quality (Group A: path-tracer rendering)** | Lift AEC Studio from "engineering-complete prototype" toward a shippable product across six task groups (A: path-tracer rendering, B: design system + micro-UX, C: user-journey completeness, D: performance + architecture, E: deliver + workflow polish, F: accessibility + documentation). Group A (Tasks 1–6) is in this milestone — the rest land in follow-up PRs. Group A adds a real CPU texture pipeline (`aec_render::texture::TextureAtlas` with bilinear sampling + box-filter MIP chains, sourced from `PbrMaterial` map fields), wires textures into `PathTraceMaterial` + `sample_bsdf` with barycentric UV interpolation + tangent-space normal-map perturbation + glTF-packed metallic-roughness sampling, adds a 3-lobe glass / transmission BSDF (Snell's-law refraction via `mat.ior`, MIS-correct `eval_bsdf` + `pdf_bsdf`, opposite-side ray offset on transmission, TIR fallback to specular), loads `.hdr` + `.exr` HDRI environment maps (`aec_render::environment::EnvironmentMap`) with precomputed marginal + conditional CDFs for importance-sampled NEE replacing the procedural Hosek-Wilkie sky, threads all three through `FinalRenderPipeline` + the PBR preview rasterizer, and adds the `aec_render::compare::ssim_*` family + bridge `render:getOutputImage` / `render:compareSsim` / `render:setEnvironmentMap` IPCs so `BeforeAfterCompare` shows real render output with a Wang-et-al.-2004 SSIM percent above the slider. Known follow-up deferred to Group D mesh-tangent pipeline: the normal-map tangent basis in `path_trace.rs::trace_path` is computed via `tangent_basis(n)` (Duff branchless construction from the shading normal) rather than threaded from per-vertex mesh tangents — correct for the planar arch-viz surfaces this milestone targets (rotation around `n` is the gauge invariance of tangent-space normal maps), but produces visible seam discontinuities on imported glTF furniture authored against a specific tangent frame. The architecturally correct fix (`tangent0/tangent1/tangent2` triple on `TriangleShading`, computation in `PathTraceScene::from_render_scene`, parallel GPU storage binding in `gpu_trace.rs`, MikkTSpace-style re-orthonormalisation at the hit) lands in Group D alongside Task 24 LOD decimation which has to track tangents through edge collapses anyway. | `IN PROGRESS` |
